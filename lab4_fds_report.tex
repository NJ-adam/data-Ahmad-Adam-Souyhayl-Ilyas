\section{Functional Dependencies of the RLMS Schema}

The FDs are derived from the relational schema of Lab~2 (itself mapped from the ER diagram of Lab~1). In every relation, the primary key determines all other attributes. Notation: $X \fd Y$ means that the value of $X$ determines the value of $Y$.

\subsection{People}
\begin{longtable}{R F J}
\toprule
\textbf{Relation} & \textbf{Functional dependency} & \textbf{Justification}\\
\midrule
\endhead
\rel{Person} & pid \fd{} firstName, lastName, email, affiliation, startDate, endDate & pid is the primary key. A person has one name, one email, one affiliation and one start/end date.\\
\rel{Student} & pid \fd{} program & pid is the primary key (and a foreign key to Person). A student is enrolled in one program (BSc, BEng, MSc or PhD).\\
\rel{Employee} & pid \fd{} phone, office, supervisorPid & pid is the primary key. ReportsTo was absorbed into Employee: only the current supervisor is kept (PE5), so each employee has at most one supervisorPid (NULL for the Dean).\\
\rel{Faculty, Administrative, Technical} & pid \fd{} position & pid is the primary key of each subclass. A staff member has one position.\\
\bottomrule
\end{longtable}

% ---------- 3. Challenges ----------
\section{Key Challenges and Resolutions}
\begin{itemize}
  \item Rules that are not FDs (no self-reporting, reservation before use, certified users only) are left to triggers or CHECKs, as in Lab~2.
  \item \texttt{unitPrice} depends on the full (supplier, consumable, laboratory) triple, and a supply may exist without stock, so Supplies and Stocks stay separate.
  \item The relationnal schema declares no \texttt{UNIQUE} clause, so FDs such as email \fd{} pid are listed as conditional.
\end{itemize}

% ---------- 4. Conversion choices ----------
\section{Justification of Conversion Choices}
\begin{itemize}
  \item ISA: one relation per class; each subclass key is also a foreign key to its parent.
  \item Weak entities: owner key + partial key, with \texttt{ON DELETE CASCADE}.
  \item Monitors is stored in Stocks (exactly one monitor per stock); Consumes references \texttt{Stocks(labId, consId)} to keep the supplying laboratory.
\end{itemize}

% ---------- 5. Assumptions ----------
\section{Assumptions}
\begin{itemize}
  \item Only the current supervisor, location and latest certification award are kept.
  \item The person with the highest authority has a NULL \texttt{supervisorPid}; a NULL \texttt{approverPid} means no approval is needed.
\end{itemize}
